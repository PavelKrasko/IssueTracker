# IssueTracker

Баг-трекер и система управления задачами в стиле Jira. Проекты с участниками и ролями, канбан-доска, спринты, релизы, иерархия задач на графе, учёт времени, комментарии с @упоминаниями, уведомления в приложении и в Telegram, вход через Google и GitHub.

**Стек:** React 18 + Vite + Tailwind CSS · Go 1.23 (chi, pgx, sqlc) · PostgreSQL 16 · Docker Compose.

```
issuetracker/
  backend/            Go API: chi + pgx + sqlc, PostgreSQL, файлы на диске или в S3, JWT в httpOnly-cookie, OAuth, Telegram-бот
  frontend/           React + Vite + Tailwind
  docs/database.md    схема БД и связи
  docker-compose.yml  PostgreSQL + API + фронтенд
```

## Функционал

### Аккаунт и вход
- Регистрация и вход по email и паролю (требования к паролю, показ/скрытие, понятные ошибки).
- Вход и регистрация через **Google** и **GitHub** (OAuth 2.0). Аккаунт с тем же email связывается автоматически.
- Профиль: имя, должность, «о себе», **фото профиля** (PNG/JPG/GIF/WebP до 2 МБ), смена пароля, подключение и отключение Google/GitHub.
- Сессии: короткий access-токен и обновляемый refresh-токен в httpOnly-cookie, выход.

### Проекты, участники, команды
- Несколько проектов, переключатель проектов, ключ проекта (`MB-12`).
- Приглашение по email: зарегистрированный человек сразу становится участником, незарегистрированный — при регистрации.
- Роли: владелец, администратор, участник, наблюдатель (только просмотр).
- Команды внутри проекта с участниками и их ролями в команде.

### Задачи
- Типы: задача, баг, история. Статусы: К выполнению → В работе → На проверке → Готово. Четыре приоритета.
- Исполнитель, автор, команда, даты начала и срока, story points, **оценка времени**.
- **Иерархия: задача → подзадачи → их подзадачи** любой глубины. Прогресс «3 из 5» в карточке, путь к родителю, защита от циклов.
- **Граф иерархии** (раздел «Иерархия»): дерево задач слева направо, цвет — статус, полоска прогресса подзадач, сворачивание веток, перетаскивание и масштаб, режим «список» для экранных дикторов.
- Вложения-картинки (до 10 на задачу, вставка скриншота через Ctrl+V, просмотр в лайтбоксе).
- Документы, привязанные к задаче.
- История изменений задачи (кто, что и когда поменял).
- **Имя git-ветки** для задачи (`bugfix/MB-12-ne-rabotaet-vhod`) и копирование команды `git checkout -b …` в один клик.
- Быстрое редактирование из карточки: статус, исполнитель, приоритет, спринт, версия.

### Совместная работа
- **Комментарии** к задачам: редактирование своих, удаление (своих или любых — для администратора), ссылки кликабельны.
- **@упоминания** в комментариях и описании: подсказка участников по `@`, выбор стрелками и Enter, упоминание подсвечивается.
- **Наблюдатели**: кнопка «Следить», автор, исполнитель, комментаторы и упомянутые подписываются автоматически.

### Уведомления
- **Колокольчик** в шапке: число непрочитанных, список событий по всем проектам, «Прочитать все», переход к задаче (в том числе в другом проекте).
- События: **вас назначили исполнителем**, вас упомянули, новый комментарий, смена статуса в задаче, за которой вы следите.
- **Telegram**: те же уведомления в чат с ботом. Подключение в профиле в один клик, выключатель уведомлений, отключение командой `/stop`.

### Планирование
- **Спринты**: бэклог, запланированные спринты, старт с датами (по умолчанию 2 недели), один активный спринт, завершение с переносом незакрытых задач в следующий спринт или бэклог.
- **График сгорания (burndown)** активного и завершённых спринтов: остаток в story points (или в задачах) против идеального темпа.
- **Релизы (версии)**: плановая дата, прогресс по задачам, статусы «в работе / просрочена / выпущена», **список изменений в Markdown** (новое / улучшения / исправлено) для копирования.
- **Учёт времени**: оценка, списание времени в формате «1ч 30м», «2h», «1д», журнал записей, остаток и перерасход.

### Обзор работы
- **Канбан-доска** с перетаскиванием (мышь, клавиатура Alt+←/→), обложки из картинок, значки подзадач и комментариев.
- **Хронология** (диаграмма Ганта): перетаскивание и растягивание сроков.
- **Список задач** с сортировкой.
- **Фильтры** (сохраняются в адресе, ссылкой можно поделиться): поиск, «только мои», исполнитель, тип, приоритет, статус, команда, **спринт**, **версия**, просроченные.
- **Статистика**: задачи по статусам и приоритетам, создано/выполнено по дням, нагрузка на исполнителей, **списанное время по участникам**.
- Глобальный поиск по задачам, горячие клавиши (C — новая задача, / — поиск, [ — свернуть панель).

### Интерфейс
- Светлая и тёмная тема (или как в системе).
- Адаптивная вёрстка: телефон, планшет, компьютер.
- Боковая панель сворачивается; пользователь сам выбирает, какие разделы в ней показывать, и их порядок.
- Доступность: навигация с клавиатуры, ARIA-роли, табличная альтернатива у диаграмм.

## Быстрый старт — всё в Docker

```bash
cp .env.example .env
# впишите JWT_SECRET (например: openssl rand -hex 32)
docker compose up --build
```

- Приложение: http://localhost:3000
- Swagger: http://localhost:8080/api/docs
- Загруженные файлы лежат в Docker volume `uploads` (для S3/MinIO: `STORAGE_DRIVER=s3` + переменные `S3_*`)

После обновления кода: `docker compose up --build -d`. Новые таблицы API создаст сам при старте (миграции), данные сохранятся.

## Разработка

```bash
# 1. PostgreSQL
docker compose up -d postgres

# 2. API (Go 1.23+)
cd backend
cp .env.example .env          # впишите JWT_SECRET
go mod tidy                   # один раз: скачает зависимости и создаст go.sum
make run                      # http://localhost:8080, миграции применятся сами

# 3. Фронтенд (в другом терминале)
cd frontend
npm install
npm run dev                   # http://localhost:5173, /api проксируется на :8080
```

WSL: держите проект в `~/`, а не в `/mnt/c` или `/mnt/d` — иначе `npm install` и сборка Go будут медленными и могут падать.

## Вход через Google и GitHub

Без ключей кнопки работают, но показывают «не настроено». Чтобы включить:

**GitHub** — https://github.com/settings/developers → New OAuth App.
- Homepage URL: `http://localhost:3000`
- Authorization callback URL: `http://localhost:3000/api/auth/oauth/github/callback`
- Client ID и сгенерированный secret → `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`

**Google** — https://console.cloud.google.com → создать проект (банковская карта не нужна, предложение free trial можно закрыть) → Google Auth Platform / OAuth consent screen → External → добавьте свой Gmail в Test users → Clients → Create client → Web application.
- Authorized JavaScript origins: `http://localhost:3000`
- Authorized redirect URI: `http://localhost:3000/api/auth/oauth/google/callback`
- Client ID и Client secret → `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`

Для запуска без Docker (Vite на 5173) замените `3000` на `5173`. Перезапустите API: `docker compose up -d api`.

## Уведомления в Telegram

1. В Telegram напишите **@BotFather** → `/newbot` → придумайте имя и username бота (должен оканчиваться на `bot`).
2. Скопируйте токен вида `123456789:AA...` в `.env`:
   ```env
   TELEGRAM_BOT_TOKEN=123456789:AAxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
3. Перезапустите API: `docker compose up -d api`. В логе появится `telegram-бот запущен`.
4. В приложении: **Профиль → Telegram → Подключить Telegram** → откроется чат с ботом → нажмите **Start**. Карточка в профиле сама покажет «Подключён».

Бот работает через long polling — публичный адрес и HTTPS не нужны, достаточно доступа к `api.telegram.org` из контейнера. Если в логе `telegram недоступен` / `timeout` — у контейнера нет интернета (часто в WSL с VPN): добавьте в конец `docker-compose.yml`

```yaml
networks:
  default:
    driver_opts:
      com.docker.network.driver.mtu: 1400
```

и/или `dns: [8.8.8.8, 1.1.1.1]` у сервиса `api`.

Что приходит в Telegram: назначение исполнителем, упоминание, комментарий и смена статуса в задачах, за которыми вы следите. Ссылка «Открыть задачу» ведёт прямо в карточку. Отключить — выключатель в профиле или `/stop` боту.

## Роли в проекте

| Роль | Может |
|---|---|
| Владелец | всё, включая удаление проекта и назначение администраторов |
| Администратор | участники, роли (кроме админов), команды, настройки проекта, удаление чужих комментариев и записей времени |
| Участник | задачи, подзадачи, комментарии, вложения, документы, спринты, версии, списание времени |
| Наблюдатель | только просмотр; может следить за задачами и получать уведомления |

Пригласить можно любой email: если человек ещё не зарегистрирован, приглашение сработает при регистрации или входе через Google/GitHub с этим адресом.
